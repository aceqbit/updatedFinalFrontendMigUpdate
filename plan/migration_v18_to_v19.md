# Migration Plan: Angular 18 → 19 (Atomic)

## Purpose
This file is the single, atomic migration plan to move the repository from Angular v18 to v19. It contains phased tasks, explicit validation gates, rollback triggers, required outputs, and the canonical checkpoint procedure (commit + `git push origin main`). Do NOT create or push tags as part of automated checkpointing.

## Prerequisites
- Ensure `report/assessment_report.md` is present and ingested.
- Recommended Node runtime: 18.x or 20.x LTS. Record `node -v` before starting.
- Create a backup branch if desired: `git checkout -b migration/v18-to-v19-pre` (optional, for human workflows).

## Phases & Tasks

Phase 0 — Pre-flight (S)
- Read `report/assessment_report.md` and confirm inventory and blockers.
- Run `npm ci` to ensure clean install environment.
- Run `npm audit --audit-level=high` and save to `report/vulnerability_report.md`.

Validation Gate: Pre-flight completes with install success (exit code 0).

Phase 1 — Core Dependency Alignment (M)
- Update Angular core packages: `npx ng update @angular/core@19 @angular/cli@19` (use `--force` only when plan explicitly requires it).
- Update TypeScript to the required version for Angular 19 as prompted by `ng update`.
- Produce file-level diffs for each `package.json` or config change: `git diff --staged --name-only` and record modified files.

Validation Gate: `npx ng build --configuration production` succeeds without migration-critical errors.

Phase 2 — Third-Party Dependency Updates (M)
- Identify libraries flagged by the assessment; upgrade to compatible versions or document mitigations.
- If peer-dependency issues occur, attempt `ng update --force`; if unresolved, retry `npm install --legacy-peer-deps` and record the chosen resolution.

Validation Gate: `npx ng build` succeeds and critical paths compile.

Phase 3 — Refactor Deprecated APIs and Bootstrapping (M-L)
- Apply minimal code refactors for deprecated APIs identified in the assessment (e.g., standalone/NgModule adjustments, change detection fixes for interval-driven updates with `ChangeDetectorRef.markForCheck()` where needed).
- Verify `main.ts` bootstrapping is correct for the target architecture and apply `refactor-bootstrapping` patterns if necessary.

Validation Gate: Targeted builds and targeted unit tests for affected components pass.

Phase 4 — Runtime Verification & Unit Tests (M)
- Enumerate all `src/**/*.spec.ts` files. Run focused per-file tests when possible, otherwise run the full suite and parse the machine-readable report.
- For failing specs, capture `git diff HEAD -- <path/to/spec.ts>`, include failure stack trace, and append remediation suggestions to `report/test_report.md`.

Validation Gate: All spec files report zero failures. Only then proceed to finalization.

Phase 5 — Final Validation & Commit (S)
- Run `npx ng build --configuration production` and the full unit test suite once more: `npx ng test --watch=false` (or CI equivalent).
- Generate `report/implementation_log.md` with per-step exit codes, timestamps, and the list of changed files and diffs.

Checkpoint (Canonical):
1. Create a concise commit: `git add -A && git commit -m "chore: complete Angular v19 migration"`.
2. Push commit to `main`: `git push origin main`.
3. Verify remote HEAD: capture the pushed commit hash and append it to `report/implementation_log.md`.

Do NOT create or push git tags as part of the automated checkpoint.

## Rollback Strategy
- For recoverable failures, create a failure branch: `git checkout -b migration-failure/v18-to-v19-<timestamp>` and save `report/implementation_log.md` with failure context.
- For destructive recovery, use `git revert` to undo specific commits. Avoid `git reset --hard` on shared branches.
- Emergency Nuke & Pave: stash, `git reset --hard <last-good-commit>`, clear `node_modules`, reinstall.

## File-level Diffs & Remediation
- For every code change applied by the implementation agent, produce a small, human-readable diff and include it in `report/implementation_log.md`.
- For any validation gate failure, include a 3-step remediation suggestion directly next to the diff to accelerate fixes.

## Outputs
- `plan/migration_plan.md` (master index)
- `plan/migration_v18_to_v19.md` (this file)
- `report/implementation_log.md` (generated by implementation)
- `report/test_report.md` (generated by unit-testing)
- `report/vulnerability_report.md` (generated during dependency updates)

## Acceptance Criteria
- Build and production bundle complete without migration-critical errors.
- All `*.spec.ts` files pass.
- Commit pushed to `main` and commit hash recorded in logs.
